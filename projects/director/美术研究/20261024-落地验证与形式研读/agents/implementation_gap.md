# 图板到可制作镜头：落地差距与最小闭环

2026-10-24，研究子任务。主 agent 正在制作《最后一张》6格叙事板 v1/v2；已读冻结文本与判据，但尚未取得实际图板，因此不是对图像的独立验收。只写本报告，未安装大软件、运行引擎、搭建管线或生成资产。

## 既有研究怎样转成这次需要检查的事情

复核的是已经保存的Bacher样章选读摘要、Minari直接访谈笔记、OpenToonz流程以及Malt/MaterialX文档笔记；本轮没有重读整本书或把旧来源算新增。

| 既有依据 | 本次具体要问 | 仍存在的落地差距 |
| --- | --- | --- |
| Bacher所引出的整体设计、研究和跨环节关系 | 六格是否使用同一视觉命题？形状、明暗、空间变化是否服务同一段落？ | 概念画的统一感不证明资产可复用、镜头可制作或工时可承担 |
| Minari中住房选择与陈设发展 | 物件的前后状态是否来自人物行为？环境改变是否被画面建立？ | 随机生成的“更温馨”背景可能同时改掉空间、道具和行为，无法知道改进来自哪里 |
| OpenToonz分镜—动态分镜—资产—布局接口 | 六格中哪些角色、道具、背景必须重复？是否有可辨认且可复用的状态？ | 六张独立插图不是六个可编辑镜头工程；补间也不自动修复造型和空间漂移 |
| Malt的成像规则、MaterialX的材质/环境分离 | 哪些表现是材质，哪些是光，哪些是镜头或合成效果？ | 生成图中的笔触、边缘光、雾和表面常已烘在一起，不能假设存在对应的独立shader或参数 |

## 新补4份官方实质正文

均为2026-10-24实际文字阅读；没有看示例图、播放视频、下载示例工程或执行操作。每份仅简要保留对本题有用的事实，后文措施另标为本项目建议。

1. **Krita Manual：Storyboard Docker**，[官方全文](https://docs.krita.org/en/reference_manual/dockers/storyboard_docker.html)。已读网页行8–185全部主体。它把图板场景与动画时间线连接，支持名称、秒/帧时长、注释及重排，导出SVG/PDF；一项可包含多个关键帧，缩略图不等于完整运动。这支持“图板可讨论、可编排”，不能推导“静态PDF已检验节奏”。

2. **Godot官方：Model export considerations**，[正文](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_3d_scenes/model_export_considerations.html)。已读行6–33全部主体。文档区分相机前向与资产前向，说明三角化、应用变换、导出rest pose以及目标引擎重新判断灯光。这里能直接学到：跨软件不能只看模型像不像，还要检查坐标、变换和成像条件。

3. **Godot官方：Advanced Import Settings**，[正文](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_3d_scenes/advanced_import_settings.html)。已读行5–108全部主体。材质可抽出为外部资源，重导入保留外部修改；源材质重命名会破坏关联，预览对话框不一定显示外部材质修改。动画也可另存，保留自定义轨道。这是可编辑与版本稳定的具体条件，并不证明已打通Blender—Godot。

4. **Krita Manual：Color Managed Workflow**，[正文](https://docs.krita.org/en/general_concepts/colors/color_managed_workflow.html)。选读行8–132，涵盖设备、工作与输出空间、ICC/OCIO及LUT显示；后续细节未读。正文建议工作文件保留工作空间和未合并图层，并区分编辑数据与显示解释。不能因两个截图颜色接近就声称色彩管线已统一。

访问边界：本轮尝试Blender官方glTF、骨骼关系、Library Overrides三页均返回402，未计正文。本轮转向可公开正常读取的上述文档；没有突破登录/付费或扩大账号权限。

## v1/v2静态叙事板能验证到哪一层

可以核对可见的构图、主体大小关系、物件是否有前后位置/状态、环境是否重复得足以比较、观看顺序是否提供线索，以及版本具体改了什么。这是“图像中可见信息”的证据，不是作者解释正确的证明。

不能据此验证持续时间、镜头运动、表演节奏、动作接触、遮挡后的形体、连续笔触稳定性、完整三维几何、可绑定的角色、可重渲染材质、目标软件的导入/编辑、跨设备色彩、工时成本或观众理解。6格中的多个形状一致，也不能证明视角切换后所有隐藏部分成立。

主写者自己的复看与独立审查应分别记录；没有实际得到的观众反馈不得用“大家能看懂”替代。v2若同时改变故事、机位、配色与人物关系，只能说综合重设计不同，不能归因某一项美术调整。

## 当前最低限度的可制作信息包

### 先映射《最后一张》的对象与六拍

以本轮已冻结的`测试前提与判据-v1.md`为准：两位合作者搬离共用版画工作室，长版画包入长扁纸板并以深蓝棉带束住，各自带走私人小箱，最后共同包件仍留门旁。它是助手练习文本，不是用户作品定稿；不加归属答案、对白或和解暗示。

建议给真实源文件固定ID：人物`C_A/C_B`，私人箱`BOX_A/BOX_B`，长版画`PRINT_01`，纸板`WRAP_01`，深蓝带`STRAP_01`，门`DOOR_01`，工作台`TABLE_01`。`PRINT_01`封装后不再凭空出现另一张；成包可用父层`PACK_01`统领原纸、纸板和棉带，隐藏纸张仍属同一对象。ID是制作提案，不要求观众读到。

| 节拍 | layout与状态必须能追踪什么 | 进入制作之前最小补件 |
| --- | --- | --- |
| 共用工作室/准备 | 两人、两私人箱、长纸与门/桌的起始关系；哪些是固定设施，哪些会搬走 | 一张俯视平面；把门、窗、桌位置锁定，角色身高与纸/箱长宽用同一比例尺登记 |
| 各自收拾 | 哪只箱属于谁，哪些工作痕迹减少；不要为了“更空”删掉门窗或改变桌尺寸 | 环境物件的保留/移出表；私人箱分别继承身份，不把单格中大小差当真实换箱 |
| 面对长版画 | 原纸的长边、图像识别点和朝向；两人怎样占据同一工作区域 | 原纸独立资产与至少一个必要侧视/遮挡说明；此处不添加决定作品归属的表情剧情 |
| 共同包装 | 原纸在纸板里，长扁轮廓与蓝带承担前后识别；谁按住哪一部分只需够清楚 | 包装前/未封完/封好三个可编辑状态；带子的接触与上下遮挡；不能仅颜色相同就认作同件物 |
| 各带私人箱离开 | 两人仍各带自己的箱；共同包件由桌到门旁的过程是否有画面信息 | 在本拍或前拍的持续时间内补包件移放的关键状态；不新增剧情，只补冻结动作所需连续性 |
| 空房留包件 | 同一门、同一放置侧、同一包件，人物与私箱已离开；“空”由对照成立 | 复用主背景，按状态关闭搬离物层；保留光线依据，避免整屋重画成另一个地点 |

比例记录先从主写者选定的图板和布局读取，未知尺寸不伪造为实测。可以选“人物身高=1”的相对标尺，给长纸、门、桌、箱子明确同一组比值；若以后转三维，再定实际单位。美术夸张可以保留，但应是有意的比例规则，而不是每格独立生成的偏差。

### 哪些改画只能算图板修订，不能冒充可控变换

- 将长纸重绘成纸板包件，能提出前后状态；不能证明纸张真放得进去、包件厚度/折法成立。二维需补封装中间状态和遮挡，三维需核实几何容纳与接触。
- 将包件从桌旁重绘到门旁，能表示新的构图；不能证明搬运路径、人物可达、重量与连续动作。应在同一空间布局中确定路径，再补关键状态，不能说两张图自动构成运输动画。
- 将有人的工作室重绘成空房，能供读者推断搬离；不能证明物件都以合理方式离场，或拍间门窗/桌面没有换位。固定背景与状态层能让修改可追踪。
- 把同一角色/蓝带跨格“画得差不多”，不能证明转身、绑带、材质或运动稳定。2D刚性箱件可先做平移/旋转与遮挡；人物转面、包裹变形、布带绕行仍需新绘或适当绑定，不能依靠全图缩放/形变代替。
- 给同一张扁平图做推拉，确实可形成一种二维镜头运动；它不能验证侧移视差、物体背面、走到桌后或真实三维摄影机改变。若表现只需平面推拉，它可以是有效选择，但应如实标明验证范围。

### 本段最小分层与重开检查

至少分：固定房间、可移走工作痕迹、两人物、两私人箱、长纸/纸板/带状态、光与效果、文字说明。成包后让相关层共享一个位置变换，私人箱随各自人物离场；接触需要时单独画手/前景遮挡层，不能为保持ID牺牲必要的逐帧重绘。

下一步只取“共同包装—移到门旁”这一个决定性变化，保留可编辑源并输出入/中/出状态。重开源文件后做一次局部修改，例如调整同一包件位置或蓝带颜色，确认角色、房间和其他格不被一同重生成。通过这一步才能说取得了一个可修改的layout/资产样本；未做持续时间与运动播放之前仍不称动画验证。

这是下一环节的具体制作建议，尚未实施；只做本段需要的内容，不建立全工作室系统。

| 文件或信息 | 最小内容 | 通过条件 |
| --- | --- | --- |
| `continuity.csv` | 格号、镜头号、角色/道具ID、进入/离开、状态前后、画面中需看清的变化 | 每个状态变化能追到图格；六格不必等于六镜头，但对应明确 |
| `space_plan.svg`或可编辑平面图 | 一个主空间、固定出入口/核心家具、人物与道具关键位置、机位方向；给一个相对尺度基准 | 画面之间的左右、距离与通行路线可解释；不依靠每格重新“发明房间” |
| `design_lock.md` | 主角身高/头身相对比例、服饰识别点、关键道具尺寸/颜色与允许变化、固定/可变事项 | 比例检查能用到图格；风格性变形与无意漂移分开记录 |
| 一个分层源文件 | 背景、角色、关键道具、光/效果、文字分开；保存与输出预览同时存在 | 改动关键道具位置或颜色无需重新生成整幅画；不是给扁平PNG改扩展名 |
| `shot_test/` | 只选一个包含关键变化的镜头，保留入点、变化中、出点以及实际帧/时长 | 先检查人物是否真能碰到物件、前后状态是否连续，再谈润饰 |
| `color_and_versions.md` | 源图工作/输出标识、是否烘入Look、alpha约定、导出版本与日期；未知项写未知 | 对比v1/v2时观看条件一致；不要只写“电影级/统一色彩” |

平面图是辅助连续性依据，不把旧几何人物动作测试恢复成训练主案。美术图板仍承载人物、环境和关系表达；平面图不能代替表演或构图。

生成图的实际限制必须写清：其可编辑源通常只有生成结果和指令，不等于绘画图层、布景几何或骨骼。需要分层时，应取得实际独立图层/透明资产或人工重绘；用自动抠图或补全产生的隐藏部分仍需复审。需要三维时，先选一个必须换视角/接触/受光的对象转成可编辑资产，不能把整张图当作已重建场景。

## 两条最小路线，选其一先完成

**二维优先路线：** 同一背景和人物设计贯穿本段，先把最关键的物件变化做成可编辑图层或连续绘制；不要求全身分件绑定。给6格设置暂定时长，组为低精度动态分镜，保留一版无解释字幕预览。若动作靠逐帧表达，就按实际增加中间状态，不用镜头推拉掩饰缺失动作。验收看的是人物行动与环境变化能否在时间中相接，不是软件特效多少。

**三维必要路线：** 仅在二维无法判断空间/接触或确需改机位时做一个镜头场景。固定单位、轴向与角色/道具比例，保留rest pose和命名；几何、材质、灯光可分别修改。先输出入/中/出三帧并核同一资产，再核一个简短运动。若跨引擎，额外做一次源文件修改后的重导入：确认位置/尺度、材质引用与自定义动画未意外丢失；不用“成功打开一次”代替可持续修改。

本轮不主张先装Godot、Malt、USD或MaterialX来完成6格。官方资料提供约束和后续测试方法，当前选择熟悉且可取得的编辑方式即可。若没有现成软件，先把状态表、尺度图和分层源落实，也应如实把时间/运动检查留为未完成。

## 工时与协作怎样留下证据

对这一小段只分四件事：图板修订、资产整理、关键镜头测试、检查回改；每件记录开始/结束、实际产物、返工原因及决定人。一个人可兼任多个岗位，但不要把子agent写作耗时当作绘画/建模成本。没有实做前仅能列估时范围，不能承诺“几小时可完成整片”。

最小交接不是再写长清单，而是把同一镜头的图板版本、资产版本、可编辑源和预览对应起来。最终记录应能回答：改了哪一件东西、影响哪些镜头、是否须重出图、谁复核了什么。若6格需要每次整板重生成而无法局部修订，该项应记为当前返工风险与落地缺口。

本报告的阶段结论：先完成整体叙事板v1/v2及实际看图审查，再把其中一个决定性变化交给可编辑镜头测试。静态图板的学习成果有实际价值，但其证据上限必须停在可见画面组织，不能由此宣布数字美术生产能力已经闭环。

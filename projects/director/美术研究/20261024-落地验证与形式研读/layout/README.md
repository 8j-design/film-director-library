## 实际完成的核对

两版均可被XML解析，共86个元素、44个唯一ID；所有`use`引用都有内部目标。实际差异仅1处：`PACK_01`的`color`属性。11项固定对象/尺寸元素逐一比对完全相同，metadata中的全部尺寸数据相同。JSON保留两版SHA-256。

这验证“原生向量布局文件能够定点修改且其他记录未变”；不包含实际渲染、屏幕观看、Blender/Godot导入、人物接触、碰撞、动画或观众测试。没有使用浏览器规避此前限制。

## 尺寸与空间的证据边界

所有数值为本练习提出的假设布局单位`u`，不是现实测量、生成图板测量或用户认可的场景设计。三个平面各使用0.75屏幕单位/u；下方对象正面尺寸索引用1屏幕单位/u。原纸160×48u，包装面164×52u；额外余量是提案，未验证纸张厚度及包装工艺。人物100u/96u为身高比较线，不是人物造型；平面中的十字只是位置锚点。

最终包件采取立靠提案，正面高164u、宽52u，俯视占地52×8u；包装面尺寸未因平面视角改小。未计算靠墙倾角、受力或足够安全的门开启间隙。路径是位移提案，未验证有人搬运、转向或动作接触。临时杂物未逐件列全，因此本件不能单独验收工作室清空的完整程度。

源依据为同级上层`测试前提与判据-v1.md`及研究报告所列公开官方文档。未来需要实际图板/布局配准时，应单独记录改动，不以本假设平面反过来宣称图板已经一致。

## 再编辑

可用任何支持标准SVG的向量编辑器，或直接修改有ID的XML。保持尺寸与固定对象时，只改目标对象组的变换/颜色；改动后应重跑同等范围的结构比对。当前脚本会重建演示原版和测试修改版，手工编辑前应另存，避免把手工稿作为脚本输出覆盖。

## 主控比较之后实际追加的尺度修补

比较发现，原布局以人物100u对原纸160u，与V2要求约110cm长纸相对成年人的尺度不一致。后补统一提案假设成人170cm，这个身高不是原提示词规定。原源和单色修改样本全部保留；另存[尺度修订SVG](space_plan_scale_revision.svg)，见[实际修补脚本](repair_scale.py)与[核对JSON](scale_repair_verification.json)。

主控实际重读原SVG，定义测试成人170cm=100u，纸张改为64.7059×23.5294u，外板68.7059×27.5294u；重读修改文件后核对比值110/170、二维容纳关系、房间与角色锚点未变，原文件字节未变。它统一的是提示词与布局的**提案尺度**；并没有量取或修复V2图板，后者仍不能宣称比例通过。未渲染/未导入软件/未验动作，当前SVG的空间方向也未配准原图。
